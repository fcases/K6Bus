## =====================================================================
PRIORIDAD INMEDIATA
1. Disenar fase intermedia de wrappers seguros generados por ProtobuZig:
   - fichero adicional tipo cctrol_api.zig.
   - tipos raw actuales permanecen en cctrol.zig.
   - wrappers API exponen initDefault/deinit, setters, appenders, getters controlados y serialize/deserialize en ingles.
   - append de repeated message debe hacer copia profunda, no transferencia owned publica.
   - getXAt(index) debe devolver copia owned que el usuario libere con deinit().
   - piloto recomendado: EstRemCtrol + EstMeteo.
2. Revisar transportes para asegurar que no conservan slices prestados de AppConfig temporal:
   - LoopTransport.
   - MCastTransport.
   - futuros BCastTransport.
   - futuros UDPStarTransport.
   - futuros UnixSocketStarTransport.
   - CrossConnectors.
3. Optimizar dispatchToSubscribers:
   - filtrar por channel y msgType antes de clone/enqueue.
   - evitar copias y encolados innecesarios cuando varios tipos comparten canal.
   - quitar o dejar como assert defensivo el filtro msgType redundante de GenericSubscriber.
4. Consolidar helpers de ergonomia restantes en ProtobuZig:
   - optional string/bytes: setX() + clearX().
   - repeated scalar: setX() + appendX().
   - repeated string/bytes: clearX() + appendX() + setX().
   - repeated message: appendX() con copia profunda y getXAt() con copia owned.
5. Anadir o consolidar helper de conversion BinaryFormat -> BinaraFormato:
   - Zig no permite asignacion directa aunque ambos sean enum(u64).
   - Usar @intFromEnum + std.meta.intToEnum.
