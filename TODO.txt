2.2. Sobrescritura de defaults owned

[PENDIENTE] Auditar legiElProtobufTeksto y otros parsers que parten de

Criterios de aceptacion:

- repeated temporal no pierde ni duplica ownership;
- un error parcial permite llamar deinit() con seguridad;
- pruebas con defaults explicitos y GPA sin leaks.

2.3. Oneof Protobuf Text no-message

[PENDIENTE] Implementar lectura y escritura para:
- scalar;
- enum;
- string;
- bytes.

Criterios de aceptacion:
- se libera la rama anterior antes de activar la nueva;
- lectura last-one-wins;
- clear deja .none;
- round-trip y pruebas de cambio de rama;
- bytes no imprimibles se representan mediante escapes definidos.

2.4. Defaults string/bytes

[PENDIENTE] Endurecer la generacion de defaults owned.

Criterios de aceptacion:
- los defaults owned se crean en initDefault();
- ningun deinit() libera literales estaticos;
- los struct literals generados no crean estados invalidos;
- pruebas de required/optional con y sin default;
- sobrescritura y deinit sin leaks.

2.5. Enums

[PENDIENTE] Validar y corregir:
- required enum sin default explicito;
- optional enum sin default;
- optional enum con default;
- repeated enum.

Criterios de aceptacion:
- required usa 0 si es valido o el primer valor declarado;
- optional sin default queda null;
- optional con default se materializa en initDefault();
- repeated comienza vacio;
- tests de generacion, compilacion y round-trip.

2.6. Helpers owned/repeated

[PENDIENTE] Completar solamente los helpers que aporten una necesidad real:
- helpers para campos repeated;
- helpers para string/bytes owned;
- valorar dupeX()/dupeXAt().

Criterios de aceptacion:
- contrato owned/borrowed documentado;
- copia preparada antes de liberar el valor previo;
- API coherente entre required, optional, repeated y oneof;
- no inflar la API con aliases redundantes.
